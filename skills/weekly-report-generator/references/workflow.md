# 周报生成器 - 完整工作流

本文档详细描述周报生成的完整 5 步工作流程。

## Step 1: 收集用户输入

需要收集以下信息：

### 1. 项目路径（必需）

- **单个项目**：`/Users/yanghongxuan/yunji/huadian/ecm-ui`
- **多个项目**：`/path/to/proj1, /path/to/proj2, /path/to/proj3`

### 2. 时间表达式（必需）

- **相对时间**：`本周`、`上周`、`本月`
- **绝对时间**：`2025.1.10 - 2025.1.15`
- **混合时间**：`上周三到今天`

### 3. 示例周报或模板文件（可选，推荐）

**方式1：直接粘贴文本内容**
- 用户直接粘贴示例周报文本
- AI 将模仿文本格式和风格

**方式2：提供模板文件路径**（推荐）
- 用户提供模板文件路径（.md 或 .docx）
- 在 Step 3.5 调用 `analyze_template.py` 分析模板
- AI 基于结构化数据精确模仿

### 4. 输出方式（必需）

- **按天分类**：按周一到周五分组展示工作内容
- **合并输出**：一周内的任务凝练合并，统一编号输出

### 5. 输出路径和文件名（必需）

- **输出路径**：`/path/to/output`
- **文件名**：`20250115周报.md` 或 `20250115周报.docx`

### 6. 命名规则（可选，多周时推荐）

- **默认规则**：`周报YYYYMMDD-YYYYMMDD.md`
- **自定义规则**：支持占位符
  - `{N}`：周序号（1、2、3...）
  - `{START}`：起始日期（YYYYMMDD）
  - `{END}`：结束日期（YYYYMMDD）
- **示例**：
  - `项目第{N}周周报.docx` → `项目第1周周报.docx`
  - `周报{START}-{END}.md` → `周报20250512-20250518.md`

## Step 2: AI解析时间 + 交互确认

AI 解析时间表达式，计算对应的日期范围：

### 解析规则

- **相对时间**：对齐到工作周（周一至周五）
- **绝对时间**：保持原样
- **混合时间**：计算实际日期范围

### 示例

- `本周` → 2025年1月13日（周一）至2025年1月17日（周五）
- `上周` → 2025年1月6日（周一）至2025年1月10日（周五）
- `2025.1.10 - 2025.1.15` → 2025年1月10日至2025年1月15日

### 交互确认

```
AI: "本周 = 2025年1月13日（周一）至2025年1月17日（周五），确认吗？"
用户: "确认" 或 "调整日期"
```

## Step 1.5: 检测时间跨度并拆分（多周情况）

### 判断标准

- **时间跨度 ≤ 7 天**：按单周处理
- **时间跨度 > 7 天**：需要按周拆分

### 拆分逻辑

1. 计算时间范围内的完整周数
2. 每周从周一开始到周日结束
3. 为每周生成独立的周报文件

### 示例

**用户输入**：`2025-5-12 到 2025-5-25`

**AI 计算**：
```
时间跨度：14天（2周）
- 第1周：2025-05-12（周一）至 2025-05-18（周日）
- 第2周：2025-05-19（周一）至 2025-05-25（周日）
```

**AI 确认**：
```
检测到时间跨度为 2 周，将生成 2 个周报文件：
1. 项目第一周周报（2025-05-12 至 2025-05-18）
2. 项目第二周周报（2025-05-19 至 2025-05-25）

确认吗？
```

### 大批量处理优化（20-50 周）

当周数 ≥ 10 时，AI 应该：

#### 1. 分批确认
```
检测到时间跨度为 30 周，将生成 30 个周报文件。

处理方式：
1. 先生成第 1 周周报供预览
2. 确认满意后，批量生成剩余 29 周

选择处理方式：
A. 逐周生成并确认（慢但可控）
B. 先预览第 1 周，确认后批量生成（推荐）
C. 直接批量生成所有周报（最快）
```

#### 2. 显示进度
```
正在处理第 1/30 周：2025-05-12 至 2025-05-18...
✅ 已生成：项目第一周周报.docx

正在处理第 2/30 周：2025-05-19 至 2025-05-25...
✅ 已生成：项目第二周周报.docx

...

⏳ 进度：15/30（50%）| 预计剩余时间：2分钟
```

#### 3. 缓存优化（推荐）

- 第一次调用时，获取整个时间范围的 Git 日志
- 后续周报直接从缓存中提取对应周的数据
- 避免重复调用 Git 命令

```python
# 伪代码示例
all_commits = get_all_commits(start_date, end_date)  # 一次性获取所有数据
for week in weeks:
    week_commits = filter_commits_by_week(all_commits, week)
    generate_report(week_commits)
```

## Step 3: 获取Git日志（脚本1）

### 重要限制

- ⚠️ **只读取 Git 日志**：AI 只能通过 `get_git_logs.py` 获取项目的提交记录
- 🚫 **禁止读取项目文件**：AI 绝对不能使用 Read、Glob、Grep 等工具读取项目内容
- 🚫 **禁止探索项目结构**：AI 不能探索项目的目录结构、源代码、配置文件等
- 📊 **只基于提交信息**：AI 只基于 Git 提交的 message 来生成周报内容

### 调用方式

```bash
# 默认调用（精简模式，推荐）
python3 ~/.claude/skills/weekly-report-generator/get_git_logs.py \
  --paths "项目路径1,项目路径2" \
  --since "2025-01-13" \
  --until "2025-01-17"

# 如需完整模式（包含 hash、author、email 等字段），添加 --no-minimal
python3 ~/.claude/skills/weekly-report-generator/get_git_logs.py \
  --paths "项目路径1,项目路径2" \
  --since "2025-01-13" \
  --until "2025-01-17" \
  --no-minimal
```

### 返回格式对比

#### 完整模式（JSON）
```json
{
  "start_date": "2025-01-13",
  "end_date": "2025-01-17",
  "total_commits": 15,
  "commits_by_day": {
    "周一": [
      {
        "hash": "abc123",
        "author": "张三",
        "email": "zhangsan@example.com",
        "message": "修复登录bug",
        "date": "2025-01-13",
        "time": "10:30",
        "weekday": "周一"
      }
    ]
  }
}
```

#### 精简模式（JSON，减少约 60% token）
```json
{
  "total": 15,
  "by_day": {
    "周一": [
      {
        "msg": "修复登录bug",
        "date": "2025-01-13",
        "wd": "周一"
      }
    ]
  }
}
```

### 字段说明

| 字段 | 完整模式 | 精简模式 | 说明 |
|------|---------|---------|------|
| 提交信息 | `message` | `msg` | 精简模式只保留第一行 |
| 日期 | `date` | `date` | 格式：YYYY-MM-DD |
| 星期 | `weekday` | `wd` | 周一到周日 |
| 哈希值 | `hash` | ❌ 移除 | 不需要 |
| 作者 | `author` | ❌ 移除 | 不需要 |
| 邮箱 | `email` | ❌ 移除 | 不需要 |
| 时间 | `time` | ❌ 移除 | 不需要 |
| 起始日期 | `start_date` | ❌ 移除 | AI 已知 |
| 结束日期 | `end_date` | ❌ 移除 | AI 已知 |
| 总数 | `total_commits` | `total` | 精简字段名 |
| 按天分组 | `commits_by_day` | `by_day` | 精简字段名 |

### AI 使用建议

- ✅ **精简模式是默认行为**：无需额外参数，自动启用精简模式
- ✅ 减少 **约 60%** token 消耗
- ✅ 保留所有必要信息（提交内容、日期、星期）
- ✅ 不影响后续的内容清洗和周报生成
- 💡 如需完整信息（hash、author、email），使用 `--no-minimal` 参数

### 特性

- 只返回工作日（周一到周五）的提交
- 支持多项目聚合
- 按天分组
- 自动跳过周末的提交
- 精简模式只保留第一行提交信息（移除多行描述）

## Step 3.5: 分析示例模板（如果用户提供）

### 条件触发

用户在 Step 1 中提供了示例周报文件路径

### 调用脚本

```bash
python3 ~/.claude/skills/weekly-report-generator/analyze_template.py \
  --template "示例周报.docx" \
  --output template_structure.json
```

### 返回数据（JSON）

```json
{
  "type": "word",
  "structure": {
    "title": "A公司集团工程部技术服务项目",
    "sections": [
      {"level": 2, "title": "工作周报", "content": ""},
      {"level": 3, "title": "一、本周工作情况", "content": ""},
      {"level": 3, "title": "二、下周工作计划", "content": ""},
      {"level": 3, "title": "三、存在问题和风险", "content": ""}
    ]
  },
  "variables": {
    "{{起始日期}}": {"name": "起始日期", "required": true, "type": "date"},
    "{{结束日期}}": {"name": "结束日期", "required": true, "type": "date"},
    "{{本周工作情况}}": {"name": "本周工作情况", "required": true, "type": "content"},
    "{{下周工作计划}}": {"name": "下周工作计划", "required": true, "type": "future_plan"},
    "{{存在问题和风险}}": {"name": "存在问题和风险", "required": false, "type": "risk"}
  },
  "raw_content": "完整模板内容..."
}
```

### 变量类型说明

- `date`：日期变量（起始日期、结束日期）
- `content`：内容变量（本周工作情况、本期工作内容等）- 由 AI 清洗 Git 日志后填充
- `future_plan`：未来规划变量（下周工作计划、工作计划等）- 由 AI 基于本周工作智能生成
- `risk`：风险变量（存在问题和风险、问题和建议等）- 由 AI 基于本周工作智能生成

### AI 使用方式

1. 读取 `template_structure.json`
2. 基于结构信息精确模仿：
   - 标题层级和格式
   - 章节标题和顺序
   - 变量占位符位置
3. 将清洗后的内容填充到模板

### 支持的功能

- ✅ 自动检测文件类型（.md / .docx）
- ✅ 提取标题层级结构
- ✅ 识别变量占位符（`{{变量名}}`）
- ✅ 返回完整的原始内容

## Step 4: AI清洗内容 + 格式化

⚠️ **重要**：AI 必须执行内容清洗，不能直接输出原始 Git 提交信息！

### 禁止行为

- ❌ 直接输出 Git 的原始提交信息
- ❌ 使用技术术语（API、接口、组件、数据库等）
- ❌ 罗列代码细节和技术实现
- ❌ 跳过内容清洗步骤

### 必须执行

- ✅ 必须基于 `report-prompts.md` 的规则清洗内容
- ✅ 将技术术语转换为业务语言
- ✅ 同类工作合并，避免碎片化
- ✅ 使用正式的汇报语言

**详细清洗规则**：参见 [`content-rules.md`](content-rules.md)

### 未来规划章节生成（重要）

如果模板包含"下周工作计划"、"存在问题和风险"等未来规划类章节，AI 必须基于本周工作内容智能生成：

**详细生成规则**：参见 [`content-rules.md#未来规划章节生成`](content-rules.md#未来规划章节生成)

### 模板变量填充流程

如果使用了模板文件，AI 需要按以下步骤填充变量：

#### 1. 分析模板变量类型

- 读取 `analyze_template.py` 返回的 `variables` 字段
- 识别每个变量的类型（`date`、`content`、`future_plan`、`risk`）

#### 2. 填充不同类型的变量

**类型1：日期变量（`date`）**
- `{{起始日期}}`：填充为周报的起始日期（如 2025年1月13日）
- `{{结束日期}}`：填充为周报的结束日期（如 2025年1月17日）

**类型2：内容变量（`content`）**
- `{{本周工作情况}}`：填充清洗后的 Git 日志
- `{{本期工作内容}}`：填充清洗后的 Git 日志
- 填充方式：将清洗后的业务语言内容直接填充

**类型3：未来规划变量（`future_plan`）** ⚠️ 需要智能生成
- `{{下周工作计划}}`：AI 基于本周工作内容智能生成
- 生成规则：
  - 基于本周已完成的工作，推测合理的后续任务
  - 使用"持续优化"、"推进"、"完善"、"扩展"等动词
  - 避免承诺具体功能（除非有明确计划）
  - 保持简洁，通常 3-5 条即可

**类型4：风险变量（`risk`）** ⚠️ 需要智能生成
- `{{存在问题和风险}}`：AI 基于本周工作内容智能生成
- 生成规则：
  - 基于本周工作中的技术难点或未完成项
  - 使用客观、专业的描述
  - 避免夸大问题或过度承诺
  - 如果没有明显问题，可以写"暂无"或留空

#### 3. 生成完整周报

- 将所有填充后的变量组合成完整周报
- 确保格式和语言风格符合模板要求
- 检查所有必需变量都已填充

## Step 6: 多周循环处理（如果时间跨度 > 7 天）

### 循环流程

```
for 每周 in 时间范围:
  1. 调用 get_git_logs.py 获取该周的日志（默认精简模式）
  2. 调用 analyze_template.py 分析模板（仅第一次）
  3. AI 清洗内容 + 生成周报
  4. 调用 export_report.py 导出文件（使用自定义命名规则）
  5. 显示进度
```

### 示例输出

```
正在处理第 1/30 周：2025-05-12 至 2025-05-18...
✅ 已生成：项目第一周周报.docx

正在处理第 2/30 周：2025-05-19 至 2025-05-25...
✅ 已生成：项目第二周周报.docx

...

✅ 全部完成！共生成 30 个周报文件。
输出目录：/Users/yanghongxuan/Desktop/report/
```
