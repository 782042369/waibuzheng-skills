# 周报生成器 - 使用示例

本文档提供周报生成器的各种使用场景示例。

## 场景1：基本周报生成

### 用户输入

```
项目路径：E:\工作\study\myproject
时间范围：本周
输出文件名：20250115周报.md
```

### 执行流程

1. AI 解析"本周" → 2025年1月13日（周一）至2025年1月17日（周五）
2. 确认："本周是2025年1月13日（周一）至2025年1月17日（周五），对吗？"
3. 用户确认
4. 调用 `get_git_logs.py` 获取日志
5. AI 清洗内容，生成周报
6. 调用 `export_report.py` 输出文件

---

## 场景2：多项目汇总

### 用户输入

```
项目路径：E:\proj1, E:\proj2, E:\proj3
时间范围：上周
输出文件名：三项目上周周报.md
```

### 执行流程

1. AI 解析"上周" → 2025年1月6日（周一）至2025年1月10日（周五）
2. 确认日期范围
3. 调用 `get_git_logs.py --paths "E:\proj1,E:\proj2,E:\proj3"` 获取所有项目的日志
4. AI 将所有项目的提交记录合并
5. 清洗内容并生成周报
6. 输出文件

### 注意事项

- 多个项目汇总时，AI 不会按项目分组
- 所有提交记录完全合并，统一编号
- 不在周报中显示项目名称

## 场景4：使用示例风格

### 用户输入（直接粘贴文本）

```
项目路径：E:\工作\study\project
时间范围：上周

示例周报：
# 项目周报

**汇报周期**: {{起始日期}} - {{结束日期}}

## 本期工作内容

{{工作内容列表}}

## 存在问题和风险

{{问题和风险}}
```

### AI 行为

AI 会模仿示例的：
- 使用 `# 项目周报` 作为标题
- 使用 `**汇报周期**: ` 格式
- 使用 `## 本期工作内容` 和 `## 存在问题和风险` 章节
- 使用编号列表格式

## 场景5：基于示例定制格式

### 用户输入

```
项目路径：E:\工作\study\project
时间范围：上周
示例周报：
  # A公司集团工程部技术服务项目
  ## 工作周报

  **汇报周期**: 2025年1月6日（周一） - 2025年1月10日（周五）

  ### 一、本期工作内容

  1. 完善仪表盘统计功能，新增项目数量展示
  2. 优化表格展示效果，支持提示文本颜色配置
  3. 扩展合同管理模块，增加企业信用代码信息项

  ### 二、存在问题和风险

  无
输出文件名：周报.md
```

### AI 严格模仿示例格式

- 使用 `# A公司集团工程部技术服务项目` 标题
- 使用 `## 工作周报` 副标题
- 使用 `### 一、本期工作内容` 和 `### 二、存在问题和风险` 章节
- 保持编号列表格式

## 场景6：使用模板文件

### 用户输入

```
项目路径：E:\工作\study\project
时间范围：上周
模板文件：/Users/yanghongxuan/Desktop/report/report.docx
输出文件名：周报.docx
```

### 执行流程

1. AI 收集输入信息
2. 解析时间范围
3. **调用 `analyze_template.py` 分析模板文件**
4. 获取模板结构：
   ```json
   {
     "type": "word",
     "structure": {
       "title": "A公司集团工程部技术服务项目",
       "sections": [...]
     },
     "variables": {
       "{{起始日期}}": {...},
       "{{结束日期}}": {...},
       "{{本周工作情况}}": {...}
     }
   }
   ```
5. 调用 `get_git_logs.py` 获取日志
6. AI 清洗内容
7. **基于模板结构填充变量**
8. 调用 `export_report.py` 生成 Word 文件

## 场景7：多周批处理（大批量生成）

### 用户输入

```
项目路径：
  - /Users/yanghongxuan/yunji/huadian/ecm-ui
  - /Users/yanghongxuan/yunji/huadian/GroupSideProjectManagementSystem
时间范围：2025-5-12 到 2026-1-16
模板文件：/Users/yanghongxuan/Desktop/report/report.docx
命名规则：项目第{N}周周报.docx
输出路径：/Users/yanghongxuan/Desktop/report/
```

### AI 响应

```
检测到时间跨度为 30 周，将生成 30 个周报文件。

处理方式：
1. 先生成第 1 周周报供预览
2. 确认满意后，批量生成剩余 29 周

选择处理方式：
A. 逐周生成并确认（慢但可控）
B. 先预览第 1 周，确认后批量生成（推荐）
C. 直接批量生成所有周报（最快）

请选择 A/B/C：
```

### 用户选择 B

```
正在处理第 1/30 周：2025-05-12 至 2025-05-18...
✅ 已生成：项目第一周周报.docx

请预览第 1 周周报，确认满意后批量生成剩余 29 周。
满意吗？（满意/不满意）
```

### 用户确认满意

```
正在批量生成剩余 29 周...

⏳ 进度：1/30（3%）
✅ 已生成：项目第一周周报.docx

⏳ 进度：2/30（7%）
✅ 已生成：项目第二周周报.docx

⏳ 进度：3/30（10%）
✅ 已生成：项目第三周周报.docx

...

⏳ 进度：30/30（100%）
✅ 已生成：项目第三十周周报.docx

✅ 全部完成！共生成 30 个周报文件。
输出目录：/Users/yanghongxuan/Desktop/report/
```

### 优化说明

1. **缓存 Git 日志**：一次性获取所有数据，避免重复调用 Git 命令
2. **显示进度**：实时显示处理进度和预计剩余时间
3. **错误处理**：如果某一周生成失败，记录错误但继续处理
4. **批量生成**：确认第 1 周满意后，自动批量生成剩余周报

**详细的多周处理指南**：参见 [`multi-week-guide.md`](multi-week-guide.md)
