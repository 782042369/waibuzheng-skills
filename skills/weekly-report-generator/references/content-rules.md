# 周报内容清洗规则

本文档详细描述 AI 如何清洗 Git 提交信息，转换为专业周报内容。

## 🚨 核心原则（不可妥协）

AI **必须**执行内容清洗，**不能**直接输出原始 Git 提交信息！

**多周批处理时特别注意**：
- ⚠️ 每周都必须执行完整的内容清洗
- ⚠️ 不能因为批处理而降低质量标准
- ⚠️ 每周完成后都要打印确认标记："已清洗内容"
- ⚠️ 如果发现某周未清洗，立即停止并报告错误

### 禁止行为

- ❌ 直接输出 Git 的原始提交信息
- ❌ 使用技术术语（API、接口、组件、数据库等）
- ❌ 罗列代码细节和技术实现
- ❌ 跳过内容清洗步骤

### 必须执行

- ✅ 必须基于 [`report-prompts.md`](report-prompts.md) 的规则清洗内容
- ✅ 将技术术语转换为业务语言
- ✅ 同类工作合并，避免碎片化
- ✅ 使用正式的汇报语言

## 内容清洗规则

详细的内容提炼标准、语言规范和术语转换表请参见 [`report-prompts.md`](report-prompts.md)。

### 快速参考：术语转换示例

| Git 原始提交（技术术语） | 清洗后（业务语言） |
|---------------------|------------------|
| 修复仪表盘数据统计错误 | 完善仪表盘统计功能，修复数据统计异常问题 |
| 仪表盘新增项目个数字段 | 新增项目数量展示，提升数据可视化能力 |
| 新增 EcmTable 表格组件 | 完善表格展示功能，优化数据呈现效果 |
| 实现 API 接口对接 | 完成系统数据对接，实现信息交互 |
| 添加 loading 状态显示 | 优化系统响应提示，提升用户体验 |
| 扩展多语言支持配置 | 完善系统国际化功能，支持多语言切换 |
| 新增进度管理功能模块 | 新增进度管理模块，完善项目管理功能 |

### 清洗示例对比

**输入（Git提交信息）**：
```
- 修复仪表盘数据统计错误
- 仪表盘新增项目个数字段
- 仪表盘图表渲染异常
- 表格组件支持提示文本颜色配置
- 合同管理增加信用代码字段
```

**输出（清洗后）**：
```markdown
1. 完善仪表盘统计功能，新增项目数量展示，修复数据统计及图表显示异常问题
2. 优化表格展示效果，支持提示文本颜色自定义配置
3. 扩展合同管理模块，增加企业信用代码信息项
```

## 未来规划章节生成

如果模板包含"下周工作计划"、"存在问题和风险"等未来规划类章节，AI 必须基于本周工作内容智能生成。

### 下周工作计划

**生成规则**：
- 基于本周已完成的工作，推测合理的后续任务
- 使用"持续优化"、"推进"、"完善"、"扩展"等动词
- 避免承诺具体功能（除非有明确计划）
- 保持简洁，通常 3-5 条即可

**示例**：
```markdown
## 下周工作计划

1. 持续优化数据可视化功能，完善交互体验
2. 推进项目管理模块的功能测试和性能优化
3. 完善系统多语言配置，扩大语言支持范围
```

### 存在问题和风险

**生成规则**：
- 基于本周工作中的技术难点或未完成项
- 使用客观、专业的描述
- 避免夸大问题或过度承诺
- 如果没有明显问题，可以写"暂无"或留空

**示例**：
```markdown
## 存在问题和风险

1. 系统性能优化仍需持续关注，避免数据量增大影响响应速度
2. 部分功能模块需要进一步测试和优化
```

## 模板变量填充

如果使用了模板文件，AI 需要按以下步骤填充变量：

### 1. 分析模板变量类型

读取 `analyze_template.py` 返回的 `variables` 字段，识别每个变量的类型：
- `date`：日期变量
- `content`：内容变量
- `future_plan`：未来规划变量（需要智能生成）
- `risk`：风险变量（需要智能生成）

### 2. 填充日期变量（`date`）

- `{{起始日期}}`：填充为周报的起始日期（如 2025年1月13日）
- `{{结束日期}}`：填充为周报的结束日期（如 2025年1月17日）

### 3. 填充内容变量（`content`）

- `{{本周工作情况}}`：填充清洗后的 Git 日志
- `{{本期工作内容}}`：填充清洗后的 Git 日志
- 填充方式：将清洗后的业务语言内容直接填充

### 4. 填充未来规划变量（`future_plan`）

AI 基于本周工作内容智能生成：
- 基于本周已完成的工作，推测合理的后续任务
- 使用"持续优化"、"推进"、"完善"、"扩展"等动词
- 避免承诺具体功能（除非有明确计划）
- 保持简洁，通常 3-5 条即可

**示例**：
```markdown
1. 持续优化数据可视化功能，完善交互体验
2. 推进项目管理模块的功能测试和性能优化
3. 完善系统多语言配置，扩大语言支持范围
```

### 5. 填充风险变量（`risk`）

AI 基于本周工作内容智能生成：
- 基于本周工作中的技术难点或未完成项
- 使用客观、专业的描述
- 避免夸大问题或过度承诺
- 如果没有明显问题，可以写"暂无"或留空

**示例**：
```markdown
1. 系统性能优化仍需持续关注，避免数据量增大影响响应速度
2. 部分功能模块需要进一步测试和优化
```
