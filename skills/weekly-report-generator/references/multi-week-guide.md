# 多周批处理指南

本文档详细描述如何处理多周批量的周报生成（20-50 周）。

## 概述

当时间跨度超过 7 天时，AI 会自动检测并按周拆分，为每周生成独立的周报文件。

## 时间跨度检测

### 判断标准

- **时间跨度 ≤ 7 天**：按单周处理
- **时间跨度 > 7 天**：需要按周拆分

### 拆分逻辑

1. 计算时间范围内的完整周数
2. 每周从周一开始到周日结束
3. 为每周生成独立的周报文件

## 示例：2 周拆分

### 用户输入

```
项目路径：/Users/yanghongxuan/yunji/huadian/ecm-ui
时间范围：2025-5-12 到 2025-5-25
模板文件：/Users/yanghongxuan/Desktop/report/report.docx
命名规则：华电第{N}周周报.docx
输出路径：/Users/yanghongxuan/Desktop/report/
```

### AI 计算

```
时间跨度：14天（2周）
- 第1周：2025-05-12（周一）至 2025-05-18（周日）
- 第2周：2025-05-19（周一）至 2025-05-25（周日）
```

### AI 确认

```
检测到时间跨度为 2 周，将生成 2 个周报文件：
1. 华电第一周周报（2025-05-12 至 2025-05-18）
2. 华电第二周周报（2025-05-19 至 2025-05-25）

确认吗？
```

## 性能优化

### 1. 缓存 Git 日志（推荐）

**问题**：重复调用 `get_git_logs.py` 获取每个周的日志，效率低

**解决方案**：一次性获取所有数据，后续周报直接从缓存提取

```python
# 伪代码示例
all_commits = get_all_commits(start_date, end_date)  # 一次性获取所有数据

for week in weeks:
    week_commits = filter_commits_by_week(all_commits, week)
    generate_report(week_commits)
```

**优点**：
- 减少文件 I/O 操作
- 避免重复调用 Git 命令
- 显著提升处理速度

### 2. 显示进度

**重要性**：大批量处理时，用户需要知道当前进度和预计剩余时间

**进度显示格式**：
```
⏳ 进度：15/30（50%）| 预计剩余时间：2分钟
```

**实现方式**：
- 记录开始时间
- 计算平均处理时间
- 估算剩余时间

### 3. 错误处理

**策略**：如果某一周生成失败，记录错误但继续处理其他周

**实现**：
```python
failed_weeks = []
successful_weeks = []

for week in weeks:
    try:
        generate_report(week)
        successful_weeks.append(week)
    except Exception as e:
        log_error(week, e)
        failed_weeks.append(week)

# 汇总报告
print(f"✅ 成功：{len(successful_weeks)} 周")
print(f"❌ 失败：{len(failed_weeks)} 周")
if failed_weeks:
    print(f"失败周次：{failed_weeks}")
```

## 命名规则

### 默认规则

格式：`周报YYYYMMDD-YYYYMMDD.md`

示例：`周报20250512-20250518.md`

### 自定义规则

支持占位符：
- `{N}`：周序号（1、2、3...）
- `{START}`：起始日期（YYYYMMDD）
- `{END}`：结束日期（YYYYMMDD）

#### 示例 1：使用序号

规则：`华电第{N}周周报.docx`

输出：
- `华电第1周周报.docx`
- `华电第2周周报.docx`
- `华电第3周周报.docx`
- ...

#### 示例 2：使用日期范围

规则：`周报{START}-{END}.md`

输出：
- `周报20250512-20250518.md`
- `周报20250519-20250525.md`
- `周报20250526-20250601.md`
- ...

#### 示例 3：混合使用

规则：`华电项目_{N}_{START}至{END}.docx`

输出：
- `华电项目_1_20250512至20250518.docx`
- `华电项目_2_20250519至20250525.docx`
- `华电项目_3_20250526至20250601.docx`
- ...

## 循环处理流程

🚨 **重要**：每周都必须执行完整的 5 个步骤，包括内容清洗！

```python
# 伪代码
for week in weeks:
    print(f"⏳ 进度：{current}/{total}（{percentage}%）")
    print(f"📍 处理第 {week.number} 周：{week.start_date} 至 {week.end_date}")

    # 1. 获取该周的日志（默认精简模式）
    commits = get_git_logs(
        paths=project_paths,
        since=week.start_date,
        until=week.end_date
        # minimal 默认为 True，无需指定
    )
    print(f"  ✅ Git 日志获取完成（共 {len(commits)} 条提交记录）")

    # 2. 分析模板（仅第一次）
    if week.is_first:
        template = analyze_template(template_file)
        print(f"  ✅ 模板分析完成")

    # 3. 🚨 清洗内容（必须执行，不能跳过）
    cleaned_content = clean_commits(commits, template)
    print(f"  ✅ 内容清洗完成（已转换术语、合并同类项）")

    # 检查点：确认是否已清洗
    if not is_cleaned(cleaned_content):
        print(f"  ❌ 错误：第 {week.number} 周未执行内容清洗")
        print(f"  💡 立即停止处理，需要重新生成该周周报")
        break

    # 4. 生成周报
    report = generate_report(cleaned_content, template)

    # 5. 导出文件
    filename = apply_naming_rule(naming_rule, week.number, week.start_date, week.end_date)
    export_report(report, output_path, filename)
    print(f"  ✅ 文件导出完成：{filename}（已清洗内容）")

print(f"✅ 全部完成！共生成 {total} 个周报文件")
print(f"输出目录：{output_path}")
```

## 注意事项

1. **命名规则**：多周时必须提供命名规则，否则文件名会重复
2. **输出路径**：确保输出路径有足够的磁盘空间
3. **模板文件**：模板文件只在第一次分析，后续周报复用结构
4. **进度显示**：大批量处理时必须显示进度，避免用户焦虑
5. **错误处理**：如果某一周生成失败，记录错误但继续处理
6. **缓存优化**：推荐一次性获取所有 Git 日志，避免重复调用
