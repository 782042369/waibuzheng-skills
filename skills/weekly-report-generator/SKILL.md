# 周报生成器

自动化生成专业周报文档，从Git提交记录转换为面向领导的工作汇报。

## 核心功能

- **灵活时间解析**：支持"本周"、"上周"、"2025.1.10-2025.1.15"等多种时间表达
- **智能内容清洗**：将技术术语转换为业务语言，去除专业名词
- **按天分组**：按周一到周五组织工作内容
- **多项目支持**：汇总多个项目的提交记录
- **自定义风格**：基于用户提供的示例周报模仿生成

## 工作流程

生成周报遵循以下5个步骤：

### Step 1: 收集用户输入

需要收集以下信息：

1. **项目路径**（必需）
   - 单个项目：`E:\工作\study\myproject`
   - 多个项目：`E:\proj1, E:\proj2, E:\proj3`

2. **时间表达式**（必需）
   - 相对时间：`本周`、`上周`、`本月`
   - 绝对时间：`2025.1.10 - 2025.1.15`
   - 混合时间：`上周三到今天`

3. **示例周报**（可选）
   - 用户可粘贴一个示例周报内容
   - AI将严格模仿示例的格式和风格
   - 包括：标题样式、章节结构、语言风格、术语使用

4. **输出文件名**（必需）
   - 用户指定输出文件名
   - 如：`20250115周报.md`

### Step 2: AI解析时间 + 交互确认

AI解析时间表达式，计算对应的日期范围：

**解析规则**：
- 相对时间对齐到工作周（周一至周五）
- 绝对时间保持原样
- 混合时间计算实际日期范围

**示例**：
- `本周` → 2025年1月13日（周一）至2025年1月17日（周五）
- `上周` → 2025年1月6日（周一）至2025年1月10日（周五）
- `2025.1.10 - 2025.1.15` → 2025年1月10日至2025年1月15日

**交互确认**：
```
AI: "本周 = 2025年1月13日（周一）至2025年1月17日（周五），确认吗？"
用户: "确认" 或 "调整日期"
```

### Step 3: 获取Git日志（脚本1）

调用 `scripts/get_git_logs.py` 获取提交记录：

```bash
python scripts/get_git_logs.py \
  --paths "项目路径1,项目路径2" \
  --since "2025-01-13" \
  --until "2025-01-17"
```

**返回格式**（JSON）：
```json
{
  "周一": [
    {"hash": "abc123", "author": "张三", "message": "修复登录bug", "time": "10:30"}
  ],
  "周二": [
    {"hash": "def456", "author": "李四", "message": "新增用户管理功能", "time": "14:20"}
  ],
  "周三": [],
  "周四": [...],
  "周五": [...]
}
```

**特性**：
- 只返回工作日（周一到周五）的提交
- 支持多项目聚合
- 按天分组
- 自动跳过周末的提交

### Step 4: AI清洗内容 + 生成周报

AI基于 `report-prompts.md` 的规则清洗内容：

**内容提炼原则**：
1. **聚焦业务价值**：不罗列代码细节，提炼"做了什么、解决了什么、带来什么效果"
2. **同类合并**：多次小修复整合为一条，避免碎片化
3. **优先级筛选**：优先功能开发、核心优化、重要修复
4. **条目控制**：控制在20条以内

**语言风格**：
- 正式简洁，符合技术岗汇报语境
- 禁止套话："综上所述""总而言之""助力""赋能"等
- 禁止动作描述："我提交了""我修改了""提交代码"
- 每条以动词开头："新增""完善""优化""修复""调整""支持"

**术语转换要求**（重要）：

| 禁止使用 | 应转换为 |
|---------|---------|
| API、接口 | 数据通道、数据对接、系统对接 |
| 前端、后端、服务端 | 页面端、系统端、服务层 |
| 组件、控件 | 功能模块、页面元素、操作区域 |
| 字段、参数 | 信息项、数据项、配置项 |
| 数据库、表 | 数据存储、数据记录 |
| 缓存、Redis | 数据缓冲、临时存储 |
| 接口响应、请求 | 系统响应、数据交互 |
| bug、issue | 问题、异常、故障 |
| 重构、封装 | 结构优化、逻辑整理 |
| 渲染、样式 | 显示效果、界面展示 |
| 联调、部署 | 系统对接测试、系统上线 |
| 分支、合并、commit | （不体现，直接描述工作内容） |
| JSON、XML、格式 | 数据格式、数据结构 |
| 权限校验、鉴权 | 权限控制、访问管理 |
| 异步、同步、并发 | （不体现，描述业务效果） |

**示例转换**：

输入（Git提交信息）：
```
- 修复仪表盘数据统计错误
- 仪表盘新增项目个数字段
- 仪表盘图表渲染异常
- 表格组件支持提示文本颜色配置
- 合同管理增加信用代码字段
```

输出（清洗后）：
```markdown
1. 完善仪表盘统计功能，新增项目数量展示，修复数据统计及图表显示异常问题
2. 优化表格展示效果，支持提示文本颜色自定义配置
3. 扩展合同管理模块，增加企业信用代码信息项
```

**基于用户示例**：
如果用户提供了示例周报，AI必须严格模仿示例的：
- 整体格式和结构
- 标题样式
- 章节组织
- 语言风格（正式/简洁/详细）
- 描述方式和术语使用习惯

### Step 5: 输出文件（脚本2）

调用 `scripts/export_report.py` 生成文件：

```bash
python scripts/export_report.py \
  --content "清洗后的周报内容" \
  --template "模板内容（或使用用户示例）" \
  --output "输出路径" \
  --filename "用户指定的文件名.md"
```

**变量替换**（使用Jinja2）：
- `{{起始日期}}` - 2025年1月13日（周一）
- `{{结束日期}}` - 2025年1月17日（周五）
- `{{工作内容列表}}` - AI清洗后的内容
- `{{问题和风险}}` - 默认"无"
- `{{提交次数}}` - 总提交次数

## 使用场景示例

### 场景1：基本周报生成

**用户输入**：
```
项目路径：E:\工作\study\myproject
时间范围：本周
输出文件名：20250115周报.md
```

**执行流程**：
1. AI解析"本周" → 2025年1月13日（周一）至2025年1月17日（周五）
2. 确认："本周是2025年1月13日（周一）至2025年1月17日（周五），对吗？"
3. 用户确认
4. 调用 `get_git_logs.py` 获取日志
5. AI清洗内容，生成周报
6. 调用 `export_report.py` 输出文件

### 场景2：多项目汇总

**用户输入**：
```
项目路径：E:\proj1, E:\proj2, E:\proj3
时间范围：上周
输出文件名：三项目上周周报.md
```

### 场景3：自定义时间范围

**用户输入**：
```
项目路径：E:\工作\study\project
时间范围：2025.1.10 - 2025.1.15
输出文件名：自定义时间周报.md
```

### 场景4：使用示例风格

**用户输入**：
```
项目路径：E:\工作\study\project
时间范围：本月
示例周报：
  # 项目周报

  **汇报周期**: 2025年1月1日 - 2025年1月31日

  ## 本期工作内容

  1. 完成了用户管理功能的开发
  2. 修复了系统登录的问题
  3. 优化了数据查询性能

  ## 存在问题和风险

  无

  ---
  **共15次提交**
输出文件名：1月周报.md
```

**AI会模仿示例的风格**：
- 使用 `# 项目周报` 作为标题
- 使用 `**汇报周期**: ` 格式
- 使用 `## 本期工作内容` 和 `## 存在问题和风险` 章节
- 使用编号列表格式
- 使用 `---` 分隔线和提交次数统计

### 场景5：基于示例定制格式

**用户输入**：
```
项目路径：E:\工作\study\project
时间范围：上周
示例周报：
  # A公司集团工程部技术服务项目
  ## 工作周报

  **汇报周期**: 2025年1月6日（周一） - 2025年1月10日（周五）

  ### 一、本期工作内容

  1. 完善仪表盘统计功能，新增项目数量展示
  2. 优化表格展示效果，支持提示文本颜色配置
  3. 扩展合同管理模块，增加企业信用代码信息项

  ### 二、存在问题和风险

  无
输出文件名：周报.md
```

**AI严格模仿示例格式**：
- 使用 `# A公司集团工程部技术服务项目` 标题
- 使用 `## 工作周报` 副标题
- 使用 `### 一、本期工作内容` 和 `### 二、存在问题和风险` 章节
- 保持编号列表格式

## 依赖安装

使用前需要安装Python依赖：

```bash
pip install gitpython jinja2
```

或使用requirements.txt：

```bash
pip install -r requirements.txt
```

**依赖清单**：
- `gitpython>=3.1.40` - Git操作
- `jinja2>=3.1.2` - 模板引擎

## 注意事项

1. **时间格式**：脚本使用 YYYY-MM-DD 格式（如 2025-01-13）
2. **路径格式**：支持Windows和Unix路径，推荐使用绝对路径
3. **非Git目录**：如果路径不是Git仓库，脚本会跳过并提示
4. **周末提交**：脚本会自动过滤周末的提交，只保留周一到周五
5. **术语转换**：AI会严格遵循术语转换表格，将技术名词转换为业务语言
6. **示例风格**：如果提供了示例周报，AI必须严格模仿，不使用默认模板

## 快速开始

1. 确保已安装依赖：`pip install gitpython jinja2`
2. 准备项目路径（Git仓库）
3. 确定时间范围（如"本周"）
4. （可选）准备示例周报
5. 按照工作流程执行5个步骤
