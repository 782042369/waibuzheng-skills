# 周报生成器

自动化生成专业周报文档，从Git提交记录转换为面向领导的工作汇报。

## 核心功能

- **灵活时间解析**：支持"本周"、"上周"、"2025.1.10-2025.1.15"等多种时间表达
- **智能内容清洗**：将技术术语转换为业务语言，去除专业名词
- **两种输出方式**：按天分类（周一到周五）或合并输出（凝练任务）
- **多项目支持**：汇总多个项目的提交记录
- **自定义风格**：基于用户提供的示例周报模仿生成

## 工作流程

生成周报遵循以下5个步骤：

### Step 1: 收集用户输入

需要收集以下信息：

1. **项目路径**（必需）
   - 单个项目：`E:\工作\study\myproject`
   - 多个项目：`E:\proj1, E:\proj2, E:\proj3`

2. **时间表达式**（必需）
   - 相对时间：`本周`、`上周`、`本月`
   - 绝对时间：`2025.1.10 - 2025.1.15`
   - 混合时间：`上周三到今天`

3. **输出方式**（必需）
   - **按天分类**：按周一到周五分组展示工作内容
   - **合并输出**：一周内的任务凝练合并，统一编号输出

4. **示例周报**（可选，推荐）
   - 用户可粘贴一个示例周报内容
   - AI将严格模仿示例的格式和风格
   - 包括：标题样式、章节结构、语言风格、术语使用

5. **输出路径和文件名**（必需）
   - 输出路径：`/path/to/output`
   - 文件名：`20250115周报.md` 或 `20250115周报.docx`

### Step 2: AI解析时间 + 交互确认

AI解析时间表达式，计算对应的日期范围：

**解析规则**：
- 相对时间对齐到工作周（周一至周五）
- 绝对时间保持原样
- 混合时间计算实际日期范围

**示例**：
- `本周` → 2025年1月13日（周一）至2025年1月17日（周五）
- `上周` → 2025年1月6日（周一）至2025年1月10日（周五）
- `2025.1.10 - 2025.1.15` → 2025年1月10日至2025年1月15日

**交互确认**：
```
AI: "本周 = 2025年1月13日（周一）至2025年1月17日（周五），确认吗？"
用户: "确认" 或 "调整日期"
```

### Step 3: 获取Git日志（脚本1）

调用 `scripts/get_git_logs.py` 获取提交记录：

```bash
python scripts/get_git_logs.py \
  --paths "项目路径1,项目路径2" \
  --since "2025-01-13" \
  --until "2025-01-17"
```

**返回格式**（JSON）：
```json
{
  "周一": [
    {"hash": "abc123", "author": "张三", "message": "修复登录bug", "time": "10:30"}
  ],
  "周二": [
    {"hash": "def456", "author": "李四", "message": "新增用户管理功能", "time": "14:20"}
  ],
  "周三": [],
  "周四": [...],
  "周五": [...]
}
```

**特性**：
- 只返回工作日（周一到周五）的提交
- 支持多项目聚合
- 按天分组
- 自动跳过周末的提交

### Step 3.5: 分析示例模板（如果用户提供）

**条件触发**：用户在 Step 1 中提供了示例周报文件路径

**调用脚本**：
```bash
python scripts/analyze_template.py \
  --template "示例周报.docx" \
  --output template_structure.json
```

**返回数据**（JSON）：
```json
{
  "type": "word",
  "structure": {
    "title": "A公司集团工程部技术服务项目",
    "sections": [
      {"level": 2, "title": "工作周报", "content": ""},
      {"level": 3, "title": "一、本期工作内容", "content": ""},
      {"level": 3, "title": "二、存在问题和风险", "content": ""}
    ]
  },
  "variables": {
    "{{起始日期}}": {"name": "起始日期", "required": true},
    "{{结束日期}}": {"name": "结束日期", "required": true},
    "{{工作内容列表}}": {"name": "工作内容列表", "required": true},
    "{{问题和风险}}": {"name": "问题和风险", "required": false}
  },
  "raw_content": "完整模板内容..."
}
```

**AI 使用方式**：
1. 读取 `template_structure.json`
2. 基于结构信息精确模仿：
   - 标题层级和格式
   - 章节标题和顺序
   - 变量占位符位置
3. 将清洗后的内容填充到模板

**支持的功能**：
- ✅ 自动检测文件类型（.md / .docx）
- ✅ 提取标题层级结构
- ✅ 识别变量占位符（`{{变量名}}`）
- ✅ 返回完整的原始内容

### Step 4: AI清洗内容 + 格式化

基于 [`report-prompts.md`](references/report-prompts.md) 的清洗规则处理 Git 提交信息。

**内容清洗**：

输入（Git提交信息）：
```
- 修复仪表盘数据统计错误
- 仪表盘新增项目个数字段
- 仪表盘图表渲染异常
- 表格组件支持提示文本颜色配置
- 合同管理增加信用代码字段
```

输出（清洗后）：
```markdown
1. 完善仪表盘统计功能，新增项目数量展示，修复数据统计及图表显示异常问题
2. 优化表格展示效果，支持提示文本颜色自定义配置
3. 扩展合同管理模块，增加企业信用代码信息项
```

**输出方式（基于用户选择）**：

**方式1：按天分类**

如果用户选择"按天分类"，AI按周一到周五组织内容：

```markdown
## 本期工作内容

### 周一
1. 完善仪表盘统计功能，新增项目数量展示
2. 优化表格展示效果，支持提示文本颜色配置

### 周二
3. 扩展合同管理模块，增加企业信用代码信息项

### 周三
4. 修复用户登录验证异常，保障账户安全性
...
```

**方式2：合并输出**

如果用户选择"合并输出"，AI将一周内的任务凝练合并，统一编号：

```markdown
## 本期工作内容

1. 完善仪表盘统计功能，新增项目数量展示，修复数据统计及图表显示异常问题
2. 优化表格展示效果，支持提示文本颜色自定义配置
3. 扩展合同管理模块，增加企业信用代码信息项
4. 修复用户登录验证异常，保障账户安全性
5. 重构数据交互处理逻辑，提升代码可维护性
...
```

**格式化（基于用户示例）**：

如果用户提供了示例周报，AI必须严格模仿示例的：
- 整体格式和结构
- 标题样式和层级
- 章节组织方式
- 语言风格（正式/简洁/详细）
- 描述方式和术语使用习惯

如果用户未提供示例，AI使用标准格式输出。

### Step 5: 导出文件（脚本2）

调用 `scripts/export_report.py` 生成文件：

```bash
# Markdown 输出（.md 扩展名）
python scripts/export_report.py \
  --content "清洗后的周报内容（AI已生成，Markdown格式）" \
  --output "输出路径" \
  --filename "周报.md"

# Word 输出（.docx 扩展名）
python scripts/export_report.py \
  --content "清洗后的周报内容（AI已生成，Markdown格式）" \
  --output "输出路径" \
  --filename "周报.docx"

# 自动文件名（默认 Markdown 格式）
python scripts/export_report.py \
  --content "清洗后的周报内容" \
  --output "输出路径" \
  --start-date "2025-01-13" \
  --end-date "2025-01-17"
```

**自动格式检测**：
- **根据 `filename` 扩展名自动检测输出格式**：
  - `.md` → Markdown 格式
  - `.docx` → Word 格式
  - 无扩展名或默认 → Markdown 格式
- **无需手动指定格式**：脚本根据文件名自动选择输出方式
- **Word 生成**：需要安装 `python-docx` 库

**自动文件名生成**：
- 格式：`周报YYYYMMDD-YYYYMMDD.md`
- 示例：`周报20250113-20250117.md`
- 默认格式：Markdown（.md）

## 工作流与工具对照

| 步骤 | 任务 | 工具/脚本 | 输入 | 输出 |
|-----|------|----------|------|------|
| 1 | 收集用户输入 | AI 对话 | 项目路径、时间表达式、输出方式、示例周报文件或文本 | 结构化需求 |
| 2 | 解析时间 | AI 计算 | 时间表达式 | 日期范围 |
| 3 | 获取 Git 日志 | get_git_logs.py | 项目路径、日期范围 | JSON 提交记录 |
| 3.5 | 分析模板 | analyze_template.py | 示例周报文件（可选） | JSON 模板结构 |
| 4 | 清洗内容 + 格式化 | AI + report-prompts.md + 模板结构 | Git 提交信息、模板结构、输出方式 | 业务语言内容（按天或合并） |
| 5 | 导出文件 | export_report.py | AI 生成的内容、文件名、输出路径 | .md 或 .docx 文件 |

## 使用场景示例

### 场景1：基本周报生成

**用户输入**：
```
项目路径：E:\工作\study\myproject
时间范围：本周
输出文件名：20250115周报.md
```

**执行流程**：
1. AI解析"本周" → 2025年1月13日（周一）至2025年1月17日（周五）
2. 确认："本周是2025年1月13日（周一）至2025年1月17日（周五），对吗？"
3. 用户确认
4. 调用 `get_git_logs.py` 获取日志
5. AI清洗内容，生成周报
6. 调用 `export_report.py` 输出文件

### 场景2：多项目汇总

**用户输入**：
```
项目路径：E:\proj1, E:\proj2, E:\proj3
时间范围：上周
输出文件名：三项目上周周报.md
```

### 场景3：自定义时间范围

**用户输入**：
```
项目路径：E:\工作\study\project
时间范围：2025.1.10 - 2025.1.15
输出文件名：自定义时间周报.md
```

### 场景4：使用示例风格

**用户输入**：

```
# 项目周报

**汇报周期**: {{起始日期}} - {{结束日期}}

## 本期工作内容

{{工作内容列表}}

## 存在问题和风险

{{问题和风险}}

```

**AI会模仿示例的风格**：
- 使用 `# 项目周报` 作为标题
- 使用 `**汇报周期**: ` 格式
- 使用 `## 本期工作内容` 和 `## 存在问题和风险` 章节
- 使用编号列表格式

### 场景5：基于示例定制格式

**用户输入**：
```
项目路径：E:\工作\study\project
时间范围：上周
示例周报：
  # A公司集团工程部技术服务项目
  ## 工作周报

  **汇报周期**: 2025年1月6日（周一） - 2025年1月10日（周五）

  ### 一、本期工作内容

  1. 完善仪表盘统计功能，新增项目数量展示
  2. 优化表格展示效果，支持提示文本颜色配置
  3. 扩展合同管理模块，增加企业信用代码信息项

  ### 二、存在问题和风险

  无
输出文件名：周报.md
```

**AI严格模仿示例格式**：
- 使用 `# A公司集团工程部技术服务项目` 标题
- 使用 `## 工作周报` 副标题
- 使用 `### 一、本期工作内容` 和 `### 二、存在问题和风险` 章节
- 保持编号列表格式

## 依赖安装

使用前需要安装Python依赖：

```bash
pip install gitpython python-docx
```

或使用requirements.txt：

```bash
pip install -r requirements.txt
```

**依赖清单**：
- `gitpython>=3.1.40` - Git操作
- `python-docx>=0.8.11` - Word文件读写（可选，仅Word输出时需要）

**注意**：
- Markdown 输出无需额外依赖（推荐）
- Word 输出需要安装 `python-docx`
- 如遇到 Python 版本问题，使用 `python3.12` 运行脚本

## 注意事项

1. **时间格式**：脚本使用 YYYY-MM-DD 格式（如 2025-01-13）
2. **路径格式**：支持Windows和Unix路径，推荐使用绝对路径
3. **非Git目录**：如果路径不是Git仓库，脚本会跳过并提示
4. **周末提交**：脚本会自动过滤周末的提交，只保留周一到周五
5. **术语转换**：AI会严格遵循术语转换表格，将技术名词转换为业务语言
6. **示例风格**：如果提供了示例周报，AI必须严格模仿，不使用默认模板
7. **自动格式检测**：
   - 脚本根据 `filename` 扩展名自动检测输出格式
   - `.md` → Markdown，`.docx` → Word
   - 无需手动指定 `--format` 参数
8. **Word 输出**：需要安装 `python-docx`，建议使用 `python3.12` 运行
